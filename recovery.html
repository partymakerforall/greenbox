FOR EACH HEIR

Make your key once.

Create a post-quantum age key. Keep the private file, send the public file, and reuse this pair for future backups.

1

Create the two files

Install age 1.3 or newer. On a Mac: brew install age. In Terminal, run:

umask 077
mkdir greenbox-heir
cd greenbox-heir
age-keygen -pq -o heir.key
age-keygen -y -o heir.recipient heir.key

umask limits access to new files. mkdir creates your folder; cd enters it. The first age command creates a random private key. The second reads it and writes its public counterpart.

The key is generated once. Restore the saved file when needed; running key generation again creates a different key.

2

Keep one. Send one.

heir.key is secret. Keep two protected copies in separate places, such as encrypted removable drives. Your password manager can hold a copy too, provided you can access it independently of this backup.

heir.recipient is public. Send it to the creator through a trusted contact method. No wallet, signature, or invitation is needed.

HOW IT WORKS

Saved keys. Shared recovery.

One key, future backups

Each heir creates an age key once and backs it up. The creator reuses its public recipient. Every new package gets a fresh random file key and fresh shares.

Your chosen number of shares

AES-256-GCM encrypts the file. Shamir splits the file key. Each share is encrypted separately to one heir using age’s ML-KEM-768 + X25519 hybrid scheme. Adding several recipients to one age file alone would let any one of them open it.

Files stay in your browser

No uploads, external scripts, analytics, or browser storage. Private inputs remain in memory until cleared or the page closes. JavaScript cannot guarantee complete memory erasure.

Security limits

This integration has not had an independent security audit. The share envelopes use post-quantum age recipients, but age’s internal file keys are 128-bit. The separate owner passphrase and minisign routes have their own security limits.

Trust and key loss

Verify public key fingerprints with the intended heirs. Keep the receipt through a trusted route; it is a fingerprint, not an owner signature. A lost private key cannot be recreated from its public recipient.

A leaked heir key can open that heir’s shares in every package using it. Any threshold of heirs can cooperate at any time. Replacing keys does not revoke old packages.
